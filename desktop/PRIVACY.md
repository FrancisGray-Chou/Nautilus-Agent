# 本地密钥存储与 GDPR 实现边界

本说明适用于当前本地 Java 桌面端和 Rust 子进程版本。**这不是 GDPR 合规认证，也不是已填写完整的面向商业部署的隐私政策。** 用户要求的明文 `.env` 存储已实现，但用户知情确认不能替代 GDPR 第 32 条所要求的、与实际风险相称的安全措施。

## 当前实现

数据

目的、位置及保留方式

DeepSeek / OpenAI / Gemini API key

由用户在 Java 设置窗口输入，经本地标准输入管道交给 Rust；明文写入当前操作系统用户的私有 `.env`。用于对应平台 HTTPS 请求的鉴权，不写进提示词。保留至用户删除。

明文存储说明版本

与密钥文件一起保存，标明应用当时使用的告知版本；不是法律意义上的完整同意或审计记录。

本机账号名、保存位置、是否已配置

用于界面显示和本地账号隔离；设置接口不回传密钥值，不存储姓名、邮箱或额外账号资料。

当前聊天与上下文

仅保存在进程内存，向用户选择的平台发送以生成回答。切换模型会沿用历史；保存/删除密钥会清空当前上下文。关闭窗口不自动保存聊天记录。

点赞、代码本地修改和批注

仅保留在当前会话内存。点赞用于本地规则生成下一句建议，不向开发者发送、不训练模型、不自动发送提示词。代码修改不会覆盖原始回复；当后续输入匹配相关代码或明确引用代码编号时，将当前代码和批注作为参考数据发给用户选择的模型平台。输入区显示本次引用，用户可取消本轮附带，也可在代码弹窗恢复原代码并清空批注。先前已发送的内容仍会存在于当前模型历史；需要清空历史时应新建对话。关闭窗口、新建对话、保存或删除密钥会清空本地点赞、编辑和批注，不会因此删除模型平台已收到的数据。

Gemini 搜索

启用的 Gemini 预设可调用 Google Search，平台决定搜索词和是否执行搜索；处理受平台条款及 API 账号设置约束。

本地应用没有开发者遥测、远程账号服务或向开发者上传密钥的功能。用户与模型平台之间的处理仍应结合平台当前合同、产品配置、数据所在地和保存政策评估；使用“自己的 key”不自动免除组织的数据保护责任。

## 账号与存储

这里的“账号”是 **操作系统用户账号**，并非新增的应用用户名/密码或云端账号。共享同一个系统账号的人不会被本应用进一步隔离。

-   macOS：`~/Library/Application Support/Nautilus/.env`
-   Linux：`$XDG_CONFIG_HOME/Nautilus/.env`，未设置时为 `~/.config/Nautilus/.env`
-   开发/测试可设置 `NAUTILUS_PROFILE_DIR` 指向独立的私有目录。
-   当前明文存储实现针对 macOS/Linux。其他系统需要增加等效的用户 ACL 后才能启用，不能只依靠隐藏文件。

Rust 将目录限制为 `0700`，文件限制为 `0600`，校验属主，拒绝符号链接和硬链接文件，校验单行密钥格式，通过临时文件和原子替换避免写入半份配置。桌面端不自动加载工程 `.env` 或继承平台 API key；终端 CLI 保持原来的工程配置行为。用户输入不会覆盖工程中开发者的密钥。

文件权限无法阻止同一系统账号下的其他进程、管理员、恶意软件、磁盘离线读取或备份副本读取明文。共享/受管设备、敏感业务、多用户服务端部署应重新评估，并优先考虑操作系统钥匙串或加密存储。本版本按用户明确要求保留明文方案，不宣称其在所有部署中满足第 32 条。

## 用户控制

每次打开桌面端都会显示密钥与隐私设置，也可以从侧栏“API 密钥与隐私”再次进入。输入框遮蔽显示；保存前需要主动勾选已阅读明文存储及第三方调用说明。该操作是对本地存储选择的确认，**不是** 对组织其他处理活动的笼统 GDPR 同意。

用户可以按平台替换或删除密钥，也可以删除全部密钥。保存或删除后，当前 Rust 客户端和聊天上下文被清空，避免继续使用旧凭据。全部删除会移除本地 `.env`。用户可通过界面显示的路径自行访问或复制自己的配置文件。

删除本地文件不等同于安全擦除磁盘、删除备份、撤销第三方平台的 API key 或删除平台已收到的数据。需要撤销平台授权时，应在相应平台账号中操作。若同时运行多个应用实例，其他已打开实例可能仍持有原来的内存副本；应关闭这些实例。

密钥不作为命令行参数传递，不写入聊天记录，不通过设置响应读回；请求解析错误不输出原始报文，已保存密钥会从后端错误消息中替换为 `[REDACTED]`。这些措施不保证 JVM/Rust 进程内存、系统转储或备份中的所有临时副本都已被擦除。

## 对外提供服务前仍需完成

是否适用 GDPR、谁是控制者/处理者以及适用的合法性基础，取决于实际运营场景；纯个人或家庭使用的适用范围也不能直接推广到提供服务的组织。若分发或运营服务，应至少结合实际情况完成：

1.  确定控制者身份、联系渠道、合法性基础、处理目的和保留期限，提供第 13/14 条所需的完整告知。
2.  评估各平台的数据处理角色、合同/DPA、子处理者和区域配置。涉及跨境传输时确认第 V 章要求的适当机制；本客户端不保证欧盟数据驻留。
3.  完成与风险相称的安全评估；判断明文存储是否可接受，必要时改为钥匙串/加密。评估是否需要 DPIA。
4.  建立访问、更正、删除、可携带、投诉和其他适用权利的处理流程，以及泄露响应、人员权限、备份保留和审计流程。

参考：[GDPR 官方文本（第 5、6、13、25、32 条及第 V 章）](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng)、[EDPB 数据安全指导](https://www.edpb.europa.eu/sme/be-compliant/secure-personal-data_en)。
